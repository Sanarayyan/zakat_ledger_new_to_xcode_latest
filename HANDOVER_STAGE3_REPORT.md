   - **What this is:** Surah/Juz fetch effects in `src/App.jsx:3710–3754,4486–4520`, calendar month fetch in `CalendarPage.jsx:143–164`, and city search in `PrayerTimes.jsx:36–52` lack a current-request guard. Several also lack a timeout/body validation.
   - **Problem:** Start A, navigate/change language/month/query to B, resolve B then A: A may overwrite B while the route/header still says B. This is the same response-order class fixed for prayer times in Stage 2, in different unfixed consumers. Calendar fetch success does not clear `error`; once a fetch fails, the error branch at line 351 can remain even after data loads.
   - **Fix:** Apply request scoping/abort and consistent timeout/schema/error/reset behaviour to each affected consumer. Test reversed responses and fail→success on the actual screen paths.
   - **If skipped:** Wrong chapter/language/month/search results or persistent error screens can appear during poor connectivity. No fabricated live-service race reproduction is claimed.

8. **Several saved-data readers crash on malformed JSON or wrong shapes — FAILED.**
   - **What this is:** Direct `JSON.parse` initializers in Hajj (`160,237`), Umrah (`94–106`), Duas (`94`), Women's Guidance (`124–167`) and Tasbih/history. `main.jsx` wraps App, but outer providers are outside the ErrorBoundary.
   - **Problem:** A saved value of `{` throws during render; a syntactically valid wrong type can break `.filter`/`.includes`. ErrorBoundary's reopen retries the same saved value, so reopening does not repair the feature. Several providers also persist defaults after partial parsing, making careless blanket fallback fixes risky.
   - **Fix:** Validate per-key shapes, retain invalid raw data for recovery and show a safe recoverable state. Test malformed and valid-but-wrong-shaped values without deleting user records.
   - **If skipped:** Migrated/corrupt local data can leave screens unusable. Native encryption protects confidentiality, not schema validity.

9. **iOS app-level required-reason privacy declaration is missing — FAILED release check.**
   - **What this is:** App uses Capacitor Preferences and native preferences; no app-owned `PrivacyInfo.xcprivacy` is present in source or built app root.
   - **Problem:** Dependencies package their own manifests (including some UserDefaults reasons), but those are their declarations. The host has not declared its own required-reason usage through Preferences.
   - **Fix:** Add a truthful app manifest to the application target with the applicable UserDefaults reason, review all host required-reason APIs, and validate the signed archive/privacy report. Capacitor's official Preferences documentation calls for the host manifest and recommends **CA92.1** for that use.
   - **If skipped:** Clean compilation does not establish App Store submission readiness. [Capacitor v8 Preferences privacy requirements](https://capacitorjs.com/docs/apis/preferences#apple-privacy-manifest-requirements).
