# Muslim Plus — final release readiness audit

What this repo does: Muslim Plus provides Quran reading, worship tools, guides, personal progress and reminders on Android and iOS, with optional Google identity and cloud calculation APIs. This review assumes public distribution and a multi-worker backend.

**10 November 2026 (IST) · Recommendation: Not Ready for Deployment Handover as an accepted release.** The owner reports that physical testing is complete on Android and iOS. The available feedback confirms several specific behaviours and identifies failures on earlier builds. It does not certify each feature or tie both completed test runs to a signed, production-configured candidate. The deployment team can use this report to prepare its environment and resolve the gates below.

Scope: React/Vite and Capacitor app, Android and iOS projects, Django/DRF API, native permissions and alerts, third-party services, privacy, and submission. Reviewed the working tree based on `7a771a15f08f7827a95e73a3d46583853a6dd298` on `versionhub-rating-mobile-qa`, including existing uncommitted changes. Diagnostic builds and tests ran in an isolated copy. The original audit edited only the report and progress tracker. The follow-up below covers the two approved fixes and their regressions. Nothing was deployed, published, uploaded, committed or pushed.

## Release blocker fixes verified on 10 November 2026

1. **Account deletion and in-flight saves.** The regression against the previous Django views reproduced the stale save returning HTTP 201 after deletion. Both views now acquire the same account lock inside a transaction and recheck the session before writing. When deletion commits first, the old save returns 401. When the save holds the lock first, PostgreSQL reports the deletion waiting, and deletion removes the newly committed record before returning 200. The tests use distinct tokens, Django API clients and database connections. Receipt retries and rollback remain covered. SQLite acquires its write lock before rechecking the session. No schema migration is needed. [PostgreSQL transaction isolation](https://www.postgresql.org/docs/current/transaction-iso.html) · [SQLite transactions](https://www.sqlite.org/lang_transaction.html)
2. **Quran index loading.** A ten-second timeout covers response headers and bodies. Both provider responses are checked before the app renders the lists. A failed or invalid response shows a message and Retry in English or Malayalam. Retry fetches both lists again in place, and leaving the screen cancels the pending load. On the built `/quran` route, Chromium showed the error and Retry after HTTP 503, invalid data and a stalled body, then displayed all 114 Surahs using public provider response fixtures. No uncaught exceptions occurred in that run. [Al Quran Cloud API](https://alquran.cloud/api)

## Other unresolved issues and accepted limitations

- **Prayer schedule vs mosque timetable:** automatic regional method and city time zone give the app one timestamp for display and scheduling. A local mosque may use a different convention; record the app time, actual delivery time, city, school, method and reference separately. Confirm late/missed alerts on hardware before classifying them as fixed. Android audible Adhan requires exact alarm access and notification permission. iOS uses a 25-second alert plus Open prayer times; mute, Focus and OS settings can affect delivery.
- **Finite reminders:** prayer, Daily Ayah and calendar events cover up to seven days; follow-up is for the current day. Reopen online to refill; missing provider data can shorten coverage. Renewal notice is best effort. Confirm concurrent iOS pending limits, reminder isolation and delivery with all enabled. Remote push is outside scope.
- **Content/offline:** six Umrah and three Women’s Guidance recordings are deliberately text-only, with a visible unavailable label. Core Quran, prayer/calendar, city search and several audio paths depend on network providers. Native compass cannot guarantee a live heading on unreliable/missing sensors; the north-up bearing is a reference.
